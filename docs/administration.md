# Руководство администратора

Документ описывает повседневные задачи по ведению каталога: работу с
карточками специалистов, модерацию отзывов, категории и учёт оплат.

## Вход в панель

Адрес админки задаётся при развёртывании; локально — `http://localhost:5174`.

Паролей нет. Вход выполняется тем же Telegram-аккаунтом, что используется в
боте, через Telegram Login Widget. Если кнопка входа не появляется, проверьте:

1. в `.env` заполнен `VITE_TELEGRAM_BOT_USERNAME` (имя бота без `@`);
2. домен админки прописан боту командой `/setdomain` у @BotFather — виджет
   работает только на разрешённом домене.

Токен выдаётся только сотрудникам. Обычный пользователь получит отказ
«Доступ в админку не разрешён» уже на входе, а не 403 на каждом действии внутри.

## Роли

| Роль | Права |
| --- | --- |
| `USER` | Обычный пользователь: смотрит каталог, оставляет отзывы |
| `MODERATOR` | Дополнительно: очередь модерации отзывов |
| `ADMIN` | Полный доступ: специалисты, категории, подписки, статистика |

Роль хранится у пользователя в базе. Первые администраторы назначаются
через переменную `ADMIN_TELEGRAM_IDS` в `.env` — список Telegram id через
запятую. После её изменения выполните:

```bash
npm run db:seed
```

Свой Telegram id можно узнать у бота [@userinfobot](https://t.me/userinfobot).

Повысить роль существующего пользователя можно и напрямую:

```bash
npm run db:studio          # открывает Prisma Studio в браузере
```

В таблице `users` найдите нужного человека и смените поле `role`.

## Специалисты

### Жизненный цикл карточки

```
DRAFT → PENDING → ACTIVE
                ↘ HIDDEN / BLOCKED
```

| Статус | Что означает |
| --- | --- |
| `DRAFT` | Черновик, в каталоге не виден |
| `PENDING` | Заявка подана, ждёт проверки администратора |
| `ACTIVE` | Опубликован, виден в каталоге, поиске и на карте |
| `HIDDEN` | Временно скрыт (например, закончилась оплата) |
| `BLOCKED` | Заблокирован за нарушения |

Дата публикации (`publishedAt`) проставляется один раз — при первом переводе
в `ACTIVE`. Повторные скрытия и публикации её не меняют, поэтому сортировка
«Новые» остаётся честной.

### Что делает интерфейс за вас

- **Slug генерируется из имени** транслитерацией, пока вы не отредактируете его
  вручную. После ручной правки автоподстановка отключается, чтобы не затирать
  осознанно выбранный адрес.
- **Дата окончания подписки** пересчитывается при выборе тарифа от даты начала.
- **Проверка полей** выполняется теми же схемами, что и на сервере, поэтому
  ошибка видна сразу в форме, а не после отправки.

### Обязательные поля

- **Имя** и **slug** — slug попадает в ссылку, только латиница, цифры и дефис,
  уникален по всему каталогу;
- **Город**;
- **Хотя бы одна категория**;
- **Хотя бы один контакт** — иначе клиент не сможет связаться.

### Координаты

Без `lat` и `lng` карточка не появится на карте и не попадёт в поиск «рядом»,
но останется доступной в каталоге и поиске. Координаты берутся из любого
геокодера — например, кликом по точке в Яндекс.Картах.

## Заявки специалистов

Специалисты подают анкеты сами через приложение: на стартовом экране выбирают
«Я оказываю услуги» и заполняют форму. Раздел «Заявки» в панели показывает две
группы, и порядок здесь не случаен.

**Новые анкеты** идут первыми: они ещё не видны в каталоге, и человек ждёт
решения. Проверьте, что заполнено осмысленно, контакты рабочие, категория
соответствует профилю, а в описании нет рекламы сторонних площадок.

**Изменённые анкеты** — правки уже опубликованных карточек. Они остаются
в каталоге, поэтому не так срочны: снимать карточку с витрины из-за
исправленной опечатки было бы неоправданно. Но просмотреть их нужно —
именно так обходят модерацию: публикуются с приличным текстом, затем
подменяют его.

**Отклонение** требует причины. Специалист увидит её в приложении, поправит
анкету и отправит заново. Пишите так, чтобы человек понял, что именно не так:
«добавьте фотографию» полезнее, чем «анкета не соответствует требованиям».

Анкета, поданная через приложение, привязана к Telegram-аккаунту, и у одного
пользователя она может быть только одна. Карточки, заведённые администратором
вручную, к аккаунтам не привязаны — их владельцы не смогут редактировать их
сами, пока вы не свяжете карточку с пользователем в базе.

## Модерация отзывов

Каждый отзыв попадает в очередь со статусом `PENDING` и не влияет на рейтинг,
пока не одобрен.

- **Одобрить** — отзыв публикуется, рейтинг специалиста пересчитывается сразу.
- **Отклонить** — обязательно укажите причину. Она видна автору отзыва в
  личном кабинете, чтобы он понимал, что исправить.

Повторная отправка отзыва тем же пользователем заменяет прежний и снова
уходит на модерацию — правкой текста обойти проверку нельзя.

Один пользователь может оставить только один отзыв на специалиста.
Владелец карточки не может оценивать сам себя.

### Что стоит отклонять

- персональные данные третьих лиц (телефоны, адреса);
- оскорбления и нецензурная лексика;
- реклама и ссылки на сторонние площадки;
- отзывы без признаков реального обращения к специалисту.

## Объявления

Раздел «Барахолка» в приложении — это доска объявлений о продаже вещей,
отдельная от каталога специалистов. Покупатель попадает в каталог товарных
категорий, устроенный так же, как главный экран услуг; счётчик на плитке
считает только опубликованные объявления, поэтому пустые категории
покупателю не показываются — но в этом разделе они видны и редактируются. Пользователь заполняет название, цену,
состояние, город, описание и добавляет фотографии; объявление попадает в
одну из товарных категорий и ждёт проверки.

### Две витрины в одной очереди

Кроме объявлений о продаже, очередь принимает записи из раздела спроса
«Люди ищут прямо сейчас» — он живёт отдельной ролью на стартовом экране,
но проверяется здесь же. В очереди они помечены ярлыком «Ищут».

Проверять их нужно иначе: готового товара, который можно оценить по
фотографии, там может не быть вовсе, поэтому смотреть надо на внятность
описания и на адекватность суммы.

Отдельный повод для отказа — запись, составленная так, чтобы выманить
чужую вещь задёшево или вытянуть контакты («ищу дорого, пишите в другом
месте»). Обычная витрина такого не допускает, и раздел спроса не должен.

### Очередь

Страница «Объявления» показывает две группы, как и очередь заявок:

- **Новые** — ещё ни разу не публиковались, на витрине их нет;
- **Изменённые** — уже опубликованы, но автор их поправил. С витрины такие
  не снимаются: иначе правка опечатки убирала бы товар из продажи на часы.
  Проверять их стоит первыми — именно так обычно и подменяют содержимое
  одобренного объявления.

Одобрение публикует объявление на витрине. Отклонение требует причины —
она приходит автору в бот, и он может исправить и отправить повторно.

### Что стоит отклонять

- Запрещённые к продаже вещи: оружие, лекарства, алкоголь, документы;
- цену-заглушку («1 ₽», «договорная» в поле цены) — она ломает сортировку
  и фильтры по цене;
- название, не описывающее товар («срочно», «читайте описание»);
- чужие фотографии из каталогов магазинов, если товар заявлен как б/у;
- категорию не по смыслу: товар в неверной категории не находят,
  а витрина превращается в свалку.

### Ограничения

Активных объявлений на аккаунт — не больше двадцати, фотографий на
объявление — не больше десяти. Название и описание проходят через тот же
фильтр контактов, что и переписка: телефоны и ссылки в них скрываются.

Автор сам отмечает товар проданным или снимает с витрины; удалённое
объявление уносит с собой фотографии и переписки по нему.

## Категории

Категории делятся на два непересекающихся набора: **услуги** — категории
каталога специалистов, **товары** — категории барахолки. Вид задаётся при
создании и потом не меняется: записи внутри перестали бы находиться.

Категория удаляется только если в ней нет ни одного специалиста или
объявления — иначе система вернёт ошибку с числом связанных записей. Чтобы убрать категорию
из каталога, не трогая карточки, снимите флаг `isActive`: она исчезнет с
главного экрана, но связи сохранятся.

Поле `sortOrder` задаёт порядок на главном экране: меньше значение — выше
в списке. Иконка — один эмодзи.

## Подписки и оплата

Платежи приложение не проводит. Администратор фиксирует факт оплаты вручную:

1. Откройте карточку специалиста.
2. Добавьте подписку: тариф, даты начала и окончания, сумма, комментарий
   (способ оплаты, номер чека).
3. Поле `subscriptionUntil` в карточке сдвигается на новую дату, если она
   больше текущей, и включается флаг `isPromoted`.

Продвинутые карточки поднимаются выше в любой сортировке каталога — в этом
и состоит смысл платного размещения.

Кнопка «Снять истёкшие подписки» на экране «Обзор» делает это вручную.
Для регулярной работы настройте вызов по расписанию:

```
POST /api/admin/subscriptions/expire
```

Метод снимает `isPromoted` со всех карточек, у которых срок уже прошёл.
Достаточно вызывать раз в сутки — например, через `cron`.

## Переписка и контакты

Заказчики и специалисты общаются во встроенном чате, а не во внешних
мессенджерах. Контакты в анкете больше не собираются и наружу не отдаются.

Смысл в том, чтобы сделка не уходила мимо площадки и чтобы в спорной ситуации
было на что сослаться. Поэтому телефоны, логины и ссылки автоматически
скрываются и в описании анкеты, и в сообщениях.

**Исходный текст сохраняется.** Если специалист писал клиенту «звоните на
номер», в базе останется оригинал сообщения — по нему видно, кто уводил
общение с площадки. Пригодится при разборе жалоб.

**Что именно скрывается.** Телефоны от семи цифр в любом написании, `@логины`,
ссылки, адреса почты — и номера, продиктованные словами: «девять ноль ноль
сто двадцать три сорок пять». Последнее считается по количеству цифр за
словами, а не по количеству слов, поэтому «два кота и три собаки» или
«работаю с восьми до девяти» под правило не попадают.

Чистятся описание анкеты, заголовок, **имя специалиста** и сообщения в чате.
Имя тоже не случайно: «Иван +79001234567» видно в списке ещё до открытия
карточки, и это был бы самый простой обход.

**Пользователя предупреждают.** При первой попытке передать контакты бот
объясняет правило: молча вычищать мало, человек не поймёт, почему собеседник
не отвечает на присланный номер, и повторит попытку. На третьей попытке
администраторы получают уведомление — дальше решать вам.

**Ограничения стоит понимать.** После первой личной встречи люди обменяются
контактами напрямую, и следующая сделка пройдёт мимо площадки. Хитрые
написания вроде «девять—ноль—ноль» через необычные разделители тоже могут
проскочить. Механизм снижает утечку, но не устраняет её.

Закрыть переписку можно, выставив `isBlocked` у диалога в базе: история
останется доступной обеим сторонам, но писать в неё будет нельзя.

## Жалобы

Раздел «Жалобы» собирает обращения пользователей на карточки и отзывы.
На объявления пожаловаться пока нельзя — если это понадобится, механизм
жалоб расширяется на них без переделки.
Причина выбирается из списка, поэтому жалобы легко группировать.

**Жалоба сама по себе ничего не меняет.** Карточка остаётся в каталоге,
отзыв — на месте. Это сделано намеренно: автоматическое скрытие по числу
жалоб превратило бы их в оружие, и согласованными обращениями конкуренты
сносили бы честные карточки.

Поэтому решение состоит из двух шагов. Сначала закройте жалобу — как
обоснованную или нет. Затем, если нарушение подтвердилось, примите меру
в своём разделе: скройте или заблокируйте карточку, отклоните отзыв.
Разделение намеренное: санкция должна быть осознанным действием, а не
побочным эффектом нажатия кнопки в чужом списке.

Один пользователь может пожаловаться на объект только раз — иначе очередь
топится в повторах и настоящие нарушения в ней теряются.

## Ответы специалистов на отзывы

Специалист может публично ответить на отзыв о себе из своего кабинета.
Ответ появляется рядом с отзывом и модерацию не проходит: он привязан
к конкретному тексту, подписан именем и злоупотребление бьёт по самому
автору. Если ответ всё же нарушает правила, на него можно пожаловаться
как на часть карточки.

## Уведомления

Приложение само сообщает пользователям о событиях через бота:

| Событие | Кого уведомляем |
| --- | --- |
| Анкета одобрена или отклонена | Специалиста, с причиной отклонения |
| Отзыв опубликован или отклонён | Автора отзыва |
| Новый опубликованный отзыв | Специалиста |
| Специалист ответил на отзыв | Автора отзыва |
| Новая анкета или отзыв на модерации | Всех администраторов и модераторов |
| Новая жалоба | Всех администраторов и модераторов |
| Подписка истекла | Специалиста |

Уведомление не приходит, если человек заблокировал бота или никогда
не начинал с ним чат — система это запоминает и больше не пытается.
Отключить отправку целиком можно переменной `NOTIFICATIONS_ENABLED=false`.

## Удаление и скрытие

Удаление карточки необратимо и уносит с собой услуги, фотографии, отзывы и
историю подписок. Если специалист лишь временно не работает — ставьте статус
«Скрыт»: карточка пропадает из каталога, поиска и с карты, но все данные
и накопленный рейтинг сохраняются, и вернуть её можно одним переключением.

То же с категориями: удалить можно только пустую, а кнопка «Скрыть» убирает
категорию с главного экрана, не трогая связанные карточки.

## Журнал действий

Все значимые действия администраторов пишутся в таблицу `audit_logs`:
кто, что и когда. Журнал нужен для разбора спорных ситуаций — например,
когда специалист утверждает, что его заблокировали без причины.

Записываются создание, изменение и удаление карточек, решения по отзывам
и отметки об оплате — с идентификатором того, кто выполнил действие.

## Резервное копирование

```bash
# Выгрузка
pg_dump "$DATABASE_URL" -Fc -f backup-$(date +%F).dump

# Восстановление
pg_restore -d "$DATABASE_URL" --clean --if-exists backup-2026-01-15.dump
```

Делайте выгрузку хотя бы раз в сутки и храните копии вне того же сервера.
У облачных провайдеров (Neon, Supabase) автоматические бэкапы включены,
но проверьте глубину хранения на вашем тарифе.

## Типовые неполадки

**Mini App не открывается, белый экран.**
Проверьте, что `MINIAPP_URL` — действующий HTTPS-адрес и что фронтенд
по нему отдаётся. Telegram не открывает `http://` и самоподписанные сертификаты.

**«Сессия истекла, переоткройте приложение».**
JWT просрочен (по умолчанию 7 дней) либо изменился `JWT_SECRET`.
Достаточно переоткрыть приложение — авторизация пройдёт заново.

**«Подпись initData не совпадает».**
`TELEGRAM_BOT_TOKEN` в `.env` не тот, которым выдана кнопка Mini App.
Убедитесь, что бот, API и кнопка меню используют один токен.

**Карта не загружается.**
Не задан или исчерпан `VITE_YANDEX_MAPS_API_KEY`. Проверьте лимиты в кабинете
разработчика Яндекса; ключ должен быть привязан к домену приложения.

**Рейтинг не изменился после одобрения отзыва.**
Пересчёт происходит в той же транзакции, что и смена статуса. Если значение
разошлось, выполните повторную модерацию любого отзыва этого специалиста —
рейтинг пересчитается по всем одобренным.
