# С чего продолжить

Записка на случай, если между сессиями прошло время. Подробности —
в [README](README.md) и [docs/](docs/).

## Запустить всё

```bash
cd ~/projects/tg-specialists
npm run start:all
```

Скрипт поднимет базу, API, оба фронтенда, туннель и бота, а в конце покажет
адреса. Остановить: `npm run stop:all`.

После перезагрузки машины **ничего не запускается само** — ни PostgreSQL,
ни туннель. Это нормально, всё поднимается той же командой.

Адрес Mini App меняется при каждом запуске: бесплатный туннель выдаёт
случайный поддомен. Скрипт сам вписывает новый адрес в `.env` и переносит
на него кнопку меню бота, так что вручную ничего править не нужно.

**Открывайте приложение командой `/start` в боте**, а не кнопкой «Каталог»
возле поля ввода: кнопка меню кешируется на серверах Telegram и после смены
адреса какое-то время ведёт на мёртвый туннель.

| Уведомления через бота | Работают |

Проверить всё разом: `npm run test:all -w @app/api`. Он поднимает
собственный API на порту 3100 и пересоздаёт базу `tgspec_test`, поэтому
рабочую базу не трогает и уведомлений в Telegram не шлёт.

Отдельные наборы (`test:e2e`, `test:admin`, `test:onboarding`, `test:uploads`,
`test:reports`, `test:chat`, `test:contacts`, `test:listings`) идут против
рабочего API на порту 3000 и рассчитывают на чистую базу. Запускать их так
не стоит: `test:e2e:reset` удаляет всех пользователей — вместе с вашим
аккаунтом и привязкой к анкете «anna-manicure».

**Барахолка — добавление сверх ТЗ.** На стартовом экране третьей строкой
идёт «Купи-продай»: внутри «Я покупаю» открывает каталог товаров по
категориям — устроенный так же, как главный экран услуг, — а «Я продаю» —
форму с названием, ценой, состоянием, городом, описанием и фотографиями. Объявление попадает в товарную категорию и ждёт проверки
модератора; наборы категорий для услуг и товаров не пересекаются. Написать
продавцу можно только во встроенном чате — там же, где идёт переписка со
специалистами.

**Отступление от ТЗ, сделанное осознанно.** В задании общение шло через
внешние мессенджеры. По решению владельца проекта контакты из анкеты убраны
полностью, а связь идёт через встроенный чат: задача — удержать заказчика
и исполнителя внутри бота. Телефоны, логины и ссылки вычищаются из сообщений
и описаний; исходники сохраняются для разбора жалоб. Подробнее — в
[docs/administration.md](docs/administration.md).

## Что дальше, по важности

**1. Развернуть в облаке.** Единственное, что отделяет готовый продукт
от работающего. Сейчас всё живёт на ноутбуке за туннелем, который рвётся
каждые пятнадцать минут: показать заказчику или пустить реальных мастеров
нельзя. Нужны постоянный домен, база и хранилище — порядок в
[docs/deployment.md](docs/deployment.md).

**2. Выбрать хранилище файлов.** Фотографии лежат на диске приложения.
Для продакшена нужен S3-совместимый бакет: Cloudflare R2, Yandex Object
Storage, Backblaze. Настройка — там же, в deployment.md. Код готов,
меняются только переменные окружения.

**3. Редактирование услуг и галереи из админки.** Последний хвост из ТЗ:
администратор может править карточку, но не прайс-лист и фотографии в ней.

Дальше по убыванию: верификация телефона со значком в карточке (заодно
естественная платная опция), статистика просмотров по дням для специалиста —
платная подписка станет осязаемой.

## Что стоит помнить

- **`.env` не в репозитории** и содержит токен бота. Копия только на этой
  машине — при переезде перенесите его отдельно.
- **История ведётся** — первый коммит сделан. Удалённых репозиториев
  нет, всё только на этой машине.
- **Администраторы** — Telegram id `6549762809` и `7727342251`, заданы
  в `ADMIN_TELEGRAM_IDS`.
- **Вход в админку локально** — по `ADMIN_DEV_TOKEN` из `.env`. Telegram
  Login Widget на `localhost` не работает, он привязан к домену.
- **Обложки демо-карточек нарисованы, а не сняты.** Настоящих фотографий
  у проекта нет, поэтому объявления и анкеты мастеров идут с обложками
  в оформлении приложения: фон в цвете категории, крупный значок, подпись.
  Файлы лежат в `apps/api/prisma/demo-photos`, перерисовываются командой
  `node scripts/demo-photos.mjs`, в хранилище попадают при сиде.
  Когда появятся настоящие снимки — их достаточно положить туда же
  под теми же именами.
- **Демо-объявления в витрине** — семь штук от служебного продавца
  с `telegramId = 1` и четыре запроса на покупку от служебного аккаунта
  с `telegramId = 2`. Написать ему можно, но ответа не будет: живого аккаунта
  за ним нет, как и за демо-мастерами. Убрать всё разом:
  `DELETE FROM users WHERE "telegramId" IN (1, 2);`
- **На объявления нельзя пожаловаться** — механизм жалоб пока знает только
  карточки и отзывы. Расширяется добавлением значения в `ReportTarget`.
- **Ключа Яндекс.Карт нет**, поэтому экран карты показывает ошибку.
  Нужен `VITE_YANDEX_MAPS_API_KEY`.
- **На машине сломан `/etc/resolv.conf`** — в нём нет ни одного `nameserver`.
  Системный резолвер macOS работает, но программы, читающие этот файл
  напрямую, падают: так не работает `cloudflared` и `nslookup`. Поэтому
  туннель поднят через ssh, а не через cloudflared.
