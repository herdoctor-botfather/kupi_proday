# Каталог специалистов — Telegram Mini App

Приложение для поиска специалистов сферы услуг внутри Telegram: каталог по
категориям, профили с рейтингом и отзывами, карта мастеров рядом. Рядом с
каталогом работает барахолка — доска объявлений о продаже вещей.
Общение между заказчиком и специалистом происходит во встроенном чате;
платежи приложение не проводит.

## Состав репозитория

```
apps/
  api/       REST API на NestJS + Prisma (PostgreSQL)
  miniapp/   Mini App: React + TypeScript + Vite
  bot/       Бот-обёртка на grammY: точка входа и deep link
  admin/     Веб-админка: модерация, каталог, категории, подписки
packages/
  shared/    Общие типы и схемы валидации — один контракт для API и фронта
```

Общий `.env` в корне обслуживает все приложения: секрет один, дублировать
его по каталогам не нужно.

## Требования

- Node.js 20.11+ (в проекте используется 22 LTS)
- PostgreSQL 14+ — через Docker, [Postgres.app](https://postgresapp.com) на macOS
  или облачный (Neon, Supabase)
- Токен бота от [@BotFather](https://t.me/BotFather)
- Ключ [JS API Яндекс.Карт](https://developer.tech.yandex.ru/services/) — для экрана карты

## Быстрый старт

```bash
# 1. Зависимости
npm install

# 2. Конфигурация
cp .env.example .env
#    Заполните минимум: DATABASE_URL, TELEGRAM_BOT_TOKEN, JWT_SECRET
#    Секрет можно сгенерировать: openssl rand -hex 32

# 3. База данных
docker compose up -d db        # или Postgres.app, или облачная строка подключения
npm run db:generate            # генерация клиента Prisma
npm run db:push                # создание таблиц
npm run db:seed                # категории, демо-карточки, администраторы

# 4. Запуск (каждая команда — в своём терминале)
npm run dev:api                # http://localhost:3000/api
npm run dev:miniapp            # http://localhost:5173
npm run dev:admin              # http://localhost:5174
npm run dev:bot                # бот в режиме long polling
```

Mini App открывается и в обычном браузере — каталог, поиск и карта работают
в гостевом режиме. Личный кабинет и отзывы требуют запуска внутри Telegram:
только оттуда приходит подписанная `initData`.

### Если Docker недоступен (macOS до 13-й версии)

Docker Desktop поддерживает только текущую и две предыдущие версии macOS.
На более старых системах поставьте [Postgres.app](https://postgresapp.com) —
он требует всего macOS 10.15+, идёт с PostGIS и не поднимает виртуальную машину.

После установки создайте базу и роль с теми же параметрами, что в
`docker-compose.yml`, чтобы строка подключения в `.env` осталась прежней:

```bash
PGBIN=/Applications/Postgres.app/Contents/Versions/17/bin
DATA="$HOME/Library/Application Support/Postgres/var-17"

"$PGBIN/initdb" -D "$DATA" -U "$USER" --encoding=UTF8 --locale=en_US.UTF-8
"$PGBIN/pg_ctl" -D "$DATA" -l "$DATA/postgres-server.log" -o "-p 5432" -w start
"$PGBIN/psql" -p 5432 -d postgres -c "CREATE ROLE app WITH LOGIN PASSWORD 'app' CREATEDB SUPERUSER;"
"$PGBIN/createdb" -p 5432 -O app tgspec
```

Сервер, запущенный так, не поднимается сам после перезагрузки. Чтобы он
стартовал автоматически, откройте Postgres.app и включите «Start automatically».

## Отладка внутри Telegram

Telegram открывает Mini App исключительно по HTTPS с внешнего адреса,
поэтому `localhost` не подойдёт. Поднимите туннель:

```bash
npm run tunnel
```

Скрипт [scripts/dev-tunnel.sh](scripts/dev-tunnel.sh) поднимает туннель, вписывает
полученный адрес в `MINIAPP_URL` и переносит на него кнопку меню бота. Он же
следит за соединением: бесплатные туннели рвутся, и после обрыва адрес меняется —
скрипт переподключается и обновляет настройки сам. Без этого при следующем
открытии приложения Telegram показал бы «no tunnel here».

Бот подхватывает новый адрес без перезапуска: вне production он перечитывает
`MINIAPP_URL`, когда файл `.env` изменился.

**Пока работаете через туннель, открывайте приложение командой `/start`,
а не кнопкой «Каталог» возле поля ввода.** Кнопка меню хранится на серверах
Telegram и обновляется с задержкой, поэтому после смены адреса какое-то время
ведёт на мёртвый туннель — вы увидите «no tunnel here». Кнопка в ответе на
`/start` формируется ботом в момент отправки и всегда указывает на живой адрес.

Если ошибка осталась, закройте приложение свайпом вниз: Telegram кеширует
страницу Mini App.

Вручную то же самое:

```bash
ssh -R 80:localhost:5173 nokey@localhost.run   # или npx cloudflared tunnel --url http://localhost:5173
# полученный https://... вписать в MINIAPP_URL, затем:
npm run setup -w @app/bot
```

Домены `trycloudflare.com`, `lhr.life`, `ngrok` и `loca.lt` уже разрешены в
`server.allowedHosts` обоих dev-серверов. Для другого туннеля добавьте его домен
в `TUNNEL_HOSTS` в `.env` — без этого Vite ответит «Blocked request»: он
отклоняет запросы с незнакомым заголовком `Host`, защищаясь от DNS rebinding.

Адрес быстрого туннеля меняется при каждом перезапуске, поэтому `MINIAPP_URL`
и настройку бота придётся обновлять заново. Для постоянной работы нужен свой домен.

## Вход в админку

Паролей нет: вход через тот же Telegram-аккаунт, что и в боте.

**В продакшене** используется Telegram Login Widget. Пропишите имя бота в
`VITE_TELEGRAM_BOT_USERNAME`, а домен админки — самому боту командой
`/setdomain` у @BotFather: без этого виджет не отрисуется. Токен выдаётся
только пользователям с ролью `ADMIN` или `MODERATOR`, остальные получают отказ
на самом входе.

**Локально** виджет не работает — он привязан к домену, а не к `localhost`.
Для разработки задайте `ADMIN_DEV_TOKEN` в `.env` и введите его на экране входа:
приложение авторизуется под первым администратором из базы. При
`NODE_ENV=production` API игнорирует эту переменную, даже если она задана.

Роли назначаются через `ADMIN_TELEGRAM_IDS` и `npm run db:seed` либо вручную
в `npm run db:studio` — подробнее в [руководстве администратора](docs/administration.md).

## Архитектура

**Авторизация.** Приложение не хранит паролей. Telegram передаёт в Mini App
строку `initData`, подписанную HMAC-SHA256 на токене бота. API проверяет
подпись и её возраст ([telegram-init-data.ts](apps/api/src/auth/telegram-init-data.ts))
и выдаёт JWT. Подделать вход, не зная токен бота, нельзя.

Тонкость: из строки проверки исключается только `hash`, а поле `signature`
в неё входит. Диагностика расхождений включается переменной `DEBUG_INIT_DATA=1` —
она печатает строку проверки в лог сервера, поэтому по умолчанию выключена.

**Один контракт.** Схемы `zod` из `packages/shared` используются и как
валидация запросов на сервере, и как типы на клиенте. Рассинхронизация
формата между фронтом и бэком становится невозможной.

**Рейтинг денормализован.** `ratingAvg` и `ratingCount` хранятся в карточке
специалиста и пересчитываются при каждой смене статуса отзыва. Это позволяет
сортировать и фильтровать каталог без агрегатов на лету.

**Поиск рядом.** Прямоугольник вокруг точки отбирает кандидатов по индексу
`(lat, lng)`, затем расстояние уточняется формулой гаверсинуса. На каталоге
до нескольких тысяч карточек этого достаточно; дальше потребуется PostGIS —
ограничение и порог описаны в [specialists.service.ts](apps/api/src/specialists/specialists.service.ts).

**Регистрация без паролей.** Отдельной авторизации нет и не нужно: Telegram
уже подтверждает личность подписью `initData`. «Регистрация исполнителя» —
это подача анкеты, а не создание учётной записи. Заказчику не нужно и этого:
на стартовом экране он выбирает роль и сразу попадает в каталог.

**Оформление не следует за темой клиента.** Mini App выдержан в тёмной
теме с кислотным акцентом: чёрный фон, лаймовые действия, заглавные
подписи с разрядкой, полупрозрачные капсулы поверх фотографий. У клиента
тема бывает светлой, и на светлом этот стиль рассыпается, поэтому палитра
задана жёстко ([global.css](apps/miniapp/src/styles/global.css)).
Размен осознанный: приложение выглядит одинаково у всех, но перестаёт
мимикрировать под клиент. Слой с палитрой идёт последним и снимается
целиком — под ним остаётся оформление, которое тему подхватывает.

**Сообщения бота — с баннером.** Список строк с эмодзи приходится
вычитывать, картинка читается одним взглядом. Баннеры нарисованы
в оформлении приложения, поэтому переход из бота в мини-приложение
не выглядит переходом в другой продукт. Telegram возвращает
идентификатор загруженного снимка, и повторные отправки идут по нему —
без него каждый `/start` заливал бы одну и ту же картинку заново.
Если картинки нет или Telegram её не принял, сообщение уходит текстом:
баннер — украшение, и терять из-за него ответ бота недопустимо.

**Бот — не заставка, а развилка.** `/start` открывает не одну кнопку
«Открыть каталог», а три двери: услуги, барахолка, своя анкета. Ссылка из
бота несёт параметр запуска, приложение читает его
([start-param.ts](apps/miniapp/src/lib/start-param.ts)) и открывает нужный
экран, минуя вопрос о роли: человек уже сказал, зачем пришёл. Числа
в приветствии живые — бот берёт их из API, а при недоступности обходится
без них, но не молчит.

Пропущенный вопрос о роли нужно чем-то возместить: тот, кто пришёл искать
исполнителя, иначе не узнал бы, что здесь можно и разместить свою анкету.
Поэтому на главной есть ссылка в кабинет анкеты, а в профиле — «Сменить роль».

**У покупателя свой каталог.** «Я покупаю» открывает экран категорий, а не
ленту всех объявлений: лента отвечает на вопрос «что появилось», но не на
вопрос «что тут вообще продают». Устройство то же, что на главном экране
услуг — поиск, плитки категорий со счётчиком, — поэтому переучиваться при
переходе между разделами не нужно. Города заменяют кнопку «Найти рядом»:
у товара нет координат, только город продавца.

**Раздел спроса — отдельная роль, а не подраздел барахолки.** «Люди ищут
прямо сейчас» стоит на стартовом экране наравне с заказчиком, исполнителем
и барахолкой: человек приходит туда не покупать и не продавать, а посмотреть,
что людям нужно, и предложить то, что у него уже есть. Внутри та же
развилка, что и в барахолке: создать свой запрос на покупку или посмотреть
чужие запросы.

Хранится это тем же типом, что и объявления, с полем `kind`: проверка
модератором, фотографии, категории и переписка у витрин общие, а различаются
подписи и смысл цены. Отдельная таблица заставила бы дублировать всё
перечисленное ради одного различия.

**Барахолка отделена от каталога.** Объявления живут в своих таблицах и в
своём наборе категорий (`CategoryKind`): у товара нет рейтинга, отзывов и
географии поиска, зато есть цена, состояние и продажа. Общий набор категорий
пришлось бы фильтровать в каждом запросе, а «Электроника» в списке услуг
сбивала бы с толку. Переписка при этом общая: диалог привязан либо к анкете,
либо к объявлению ([chat.service.ts](apps/api/src/chat/chat.service.ts)).

**Общение удерживается на площадке.** Контакты специалиста наружу не отдаются,
а телефоны, логины и ссылки вычищаются из сообщений и описаний
([contacts.ts](packages/shared/src/contacts.ts)). Иначе контроль был бы
декорацией: специалист написал бы номер в первом же сообщении. Исходный текст
сохраняется — без него нельзя доказать, что клиента уводили с площадки.

Полностью удержать людей нельзя: после первой встречи они обменяются
контактами вживую. Механизм рассчитан на снижение утечки, а не на её
устранение.

**Уведомления — главное преимущество Mini App.** У приложения уже есть чат
с каждым пользователем, поэтому решения по анкете, судьба отзыва и новые
заявки доходят до адресата сами. Отправка намеренно не влияет на исход
операции: если Telegram недоступен, отзыв всё равно будет одобрен. Тех, кто
заблокировал бота, система запоминает и больше не тревожит.

**Жалобы не действуют автоматически.** Скрытие карточки по числу жалоб
превратило бы их в оружие против конкурентов, поэтому жалоба лишь ставит
объект в очередь к человеку.

**Картинки не в базе.** Фотографии лежат в объектном хранилище, а в базе
только ссылка и ключ. Ключ нужен, чтобы удалить файл при замене: по одному
URL это невозможно, у драйверов разные схемы адресов. Уменьшение снимка
происходит в браузере — это экономит трафик пользователя и избавляет сервер
от нативных зависимостей вроде `sharp`.

**Карты изолированы.** Провайдер вынесен в [yandex-maps.ts](apps/miniapp/src/lib/yandex-maps.ts)
и `MapPage`. Переход на Google Maps или OpenStreetMap затрагивает только эти файлы.

**Два разных механизма подписи Telegram.** Mini App присылает `initData`,
подписанную ключом `HMAC("WebAppData", токен)`; Login Widget в админке — данные,
подписанные ключом `SHA256(токен)`. Алгоритмы несовместимы, поэтому проверки
живут в [разных файлах](apps/api/src/auth/), а не в одной функции с флагом:
перепутать их молча невозможно, подпись просто не сойдётся.

## Полезные команды

| Команда | Что делает |
| --- | --- |
| `npm run typecheck` | Проверка типов во всех пакетах |
| `npm run test -w @app/api` | Тесты подписи Telegram и гео-расчётов |
| `npm run test:e2e -w @app/api` | Сквозной сценарий каталога против живой базы |
| `npm run test:admin -w @app/api` | Сценарий админки: права, категории, карточки, подписки |
| `npm run test:onboarding -w @app/api` | Выбор роли и подача анкеты специалистом |
| `npm run test:uploads -w @app/api` | Загрузка изображений и работа с галереей |
| `npm run test:reports -w @app/api` | Ответы на отзывы и жалобы |
| `npm run test:contacts -w @app/api` | Вычистка контактов из текстов (без базы) |
| `npm run test:chat -w @app/api` | Внутренний чат: доступ, фильтр, непрочитанное |
| `npm run test:listings -w @app/api` | Барахолка: размещение, модерация, витрина, фильтры |
| `npm run test:all -w @app/api` | Все наборы подряд на отдельной базе |
| `npm run test:e2e:reset -w @app/api` | Вернуть базу в состояние после сида |
| `npm run build` | Сборка всех приложений |
| `npm run db:studio` | Prisma Studio — просмотр и правка данных |
| `npm run db:migrate -w @app/api` | Создание миграции |
| `npm run setup -w @app/bot` | Команды, описание и кнопка меню бота |
| `npm run check:messages -w @app/bot` | Разметка сообщений бота — без доставки кому-либо |
| `node scripts/demo-photos.mjs` | Перерисовать обложки демонстрационных карточек |
| `node scripts/bot-images.mjs` | Перерисовать баннеры сообщений бота |

Отдельные наборы (`test:e2e` и далее) идут против того API, что запущен на
порту 3000, и рассчитывают на чистую базу — перед ними нужен
`test:e2e:reset`. Он удаляет всех пользователей, включая ваш аккаунт и
привязку к анкете, поэтому на рабочей базе так делать не стоит.
`test:all` от этого избавлен: он поднимает свой API на порту 3100 и
пересоздаёт базу `tgspec_test`, ничего не трогая в рабочей.
