# Развёртывание

Telegram открывает Mini App только по HTTPS с публичного домена, поэтому
минимальный рабочий контур — домен, TLS-сертификат и PostgreSQL.

## Что где живёт

| Компонент | Что это | Требования |
| --- | --- | --- |
| `apps/api` | Node-процесс, слушает порт | Доступ к PostgreSQL |
| `apps/miniapp` | Статика после сборки | Раздача любым веб-сервером или CDN |
| `apps/bot` | Долгоживущий процесс (long polling) | Исходящий доступ к api.telegram.org |
| PostgreSQL | База | Регулярные бэкапы |

Бот и API — отдельные процессы: перезапуск API не роняет бота, и наоборот.

## Вариант 1. VPS с Docker

Подходит, когда нужен полный контроль и предсказуемая стоимость (~5 $/мес).

```bash
git clone <репозиторий> && cd tg-specialists
cp .env.example .env      # заполните боевые значения
docker compose -f docker-compose.prod.yml up -d
```

Перед боевым запуском обязательно:

- `NODE_ENV=production` — отключает вход в админку по `ADMIN_DEV_TOKEN`;
- `JWT_SECRET` — новый, `openssl rand -hex 32`, не тот, что на локальной машине;
- `CORS_ORIGINS` — только реальные домены Mini App и админки;
- пароль PostgreSQL — не `app` из примера;
- порт 5432 **не** публиковать наружу.

TLS проще всего повесить на Caddy — он получает сертификат Let's Encrypt сам:

```caddy
app.example.com {
    root * /srv/miniapp
    try_files {path} /index.html      # SPA: любой путь отдаёт index.html
    file_server
    handle /api/* {
        reverse_proxy api:3000
    }
}
```

`try_files` обязателен: без него прямая ссылка на `/specialist/anna` вернёт 404,
потому что такого файла на диске нет — маршрут разбирает уже загруженное приложение.

### Про адрес API

Фронтенд обращается к API по относительному пути `/api/...`, то есть на тот же
домен, откуда загрузилась страница. Поэтому `VITE_API_URL` в такой схеме
**остаётся пустым**, а веб-сервер проксирует `/api` на бэкенд — как в примере выше.

Заполнять `VITE_API_URL` нужно, только если API живёт на отдельном домене
(например, фронт на Vercel, а бэкенд на Railway). Тогда обязательно добавьте
домен фронтенда в `CORS_ORIGINS`, иначе браузер заблокирует запросы.

Не путайте с `API_PROXY_TARGET`: это адрес для прокси dev-сервера, он читается
только при разработке и в собранный клиентский код не попадает. Переменные с
префиксом `VITE_` попадают в бандл и видны любому — секретов там быть не должно.

## Вариант 2. Облачные сервисы

Быстрее стартовать, бесплатно на небольших объёмах:

- **База** — [Neon](https://neon.tech) или [Supabase](https://supabase.com).
  Строку подключения берите с `?sslmode=require`.
- **API и бот** — [Railway](https://railway.app) или [Render](https://render.com).
  Два отдельных сервиса из одного репозитория: команды `npm run start -w @app/api`
  и `npm run start -w @app/bot`.
- **Mini App** — [Vercel](https://vercel.com) или Cloudflare Pages.
  Каталог сборки `apps/miniapp/dist`, обязательно настройте SPA-fallback на `index.html`.

Домен и HTTPS эти платформы дают из коробки.

## Хранилище фотографий

Аватары специалистов и снимки работ лежат в объектном хранилище, а не в базе:
картинки раздули бы её и сделали бэкапы неподъёмными.

Драйвер выбирается переменной `STORAGE_DRIVER`.

**`local`** — файлы на диске рядом с приложением. Годится только для
разработки: при нескольких экземплярах API каждый увидит лишь свои файлы,
а пересоздание контейнера сотрёт всё, что не лежит на подключённом томе.
На VPS с одним экземпляром допустимо, если смонтировать том и раздавать
каталог через nginx, минуя Node.

**`s3`** — любое S3-совместимое хранилище. Протокол один, отличаются только
адрес и регион:

| Провайдер | `S3_ENDPOINT` | `S3_REGION` |
| --- | --- | --- |
| Cloudflare R2 | `https://<account>.r2.cloudflarestorage.com` | `auto` |
| Yandex Object Storage | `https://storage.yandexcloud.net` | `ru-central1` |
| Backblaze B2 | `https://s3.<region>.backblazeb2.com` | регион бакета |
| MinIO | адрес вашего сервера | любой, плюс `S3_FORCE_PATH_STYLE=true` |

`S3_PUBLIC_URL` — адрес, по которому файлы отдаются читателям: публичный
домен бакета или CDN перед ним. Он попадает в базу вместе со ссылкой,
поэтому менять его после накопления данных болезненно — выберите сразу.

Бакет должен отдавать объекты публично на чтение, но запрещать листинг:
ключи содержат случайную часть, и без листинга чужие файлы не перебрать.

Проверка после настройки: загрузите фото в анкете и убедитесь, что ссылка
ведёт на ваш домен хранилища, а не на `/uploads/`.

## Порядок первого запуска

```bash
npm ci                          # воспроизводимая установка по package-lock.json
npm run build                   # сборка всех приложений
npm run db:generate -w @app/api
npm run db:migrate -w @app/api  # применение миграций (в проде — не db:push)
npm run db:seed                 # категории и администраторы
npm run setup -w @app/bot       # команды бота и кнопка меню
```

`db:push` меняет схему без истории изменений — он удобен на разработке,
но в продакшене используйте `db:migrate`, иначе откатить изменение будет нечем.

## После деплоя — проверьте

1. `curl https://app.example.com/api/health` → `{"status":"ok"}`
2. Откройте бота, нажмите кнопку меню — Mini App должен запуститься.
3. Внутри приложения зайдите в «Профиль»: если видно ваше имя из Telegram —
   авторизация по `initData` работает.
4. Откройте карту — маркеры должны появиться (нужен ключ Яндекс.Карт).
5. Оставьте тестовый отзыв и проверьте, что он появился в очереди модерации.

## Резервные копии

```bash
/opt/tgspec/scripts/backup.sh           # снять копию
/opt/tgspec/scripts/restore.sh          # показать список копий
/opt/tgspec/scripts/restore.sh 2026-08-31_03-15   # восстановить
```

Копия состоит из двух частей: дамп базы и архив загруженных файлов.
Порознь они бесполезны — без фотографий восстановленная база покажет
карточки с битыми картинками, а без базы фотографии останутся папкой
с файлами, о которых ничего не известно.

Копии лежат в `/opt/tgspec-backups`, хранятся две недели. Чтобы снимать
их каждую ночь, добавьте задание:

```bash
crontab -e
0 3 * * * /opt/tgspec/scripts/backup.sh >> /var/log/tgspec-backup.log 2>&1
```

Копии на том же диске защищают от ошибки в данных, но не от потери
сервера. Когда данные станут ценными, копии стоит увозить наружу —
в объектное хранилище или на другую машину.

Восстановление останавливает приложение на время работы и требует
ввести слово подтверждения: всё, что появилось после копии, пропадёт.

## Регулярное обслуживание

| Задача | Периодичность |
| --- | --- |
| Резервная копия БД | Ежедневно |
| `POST /api/admin/subscriptions/expire` | Ежедневно, по `cron` |
| Обновление зависимостей | Ежемесячно |
| Проверка лимитов Яндекс.Карт | Ежемесячно |

Пример задания `cron` для снятия истёкших подписок:

```cron
0 3 * * * curl -s -X POST -H "Authorization: Bearer $ADMIN_TOKEN" \
  https://app.example.com/api/admin/subscriptions/expire
```

## Заметки по безопасности

- `TELEGRAM_BOT_TOKEN` — это и ключ проверки подписи, и доступ к боту.
  При утечке немедленно перевыпустите его через @BotFather.
- Смена `JWT_SECRET` разлогинивает всех пользователей — это штатный способ
  экстренно прекратить все сессии.
- API отдаёт контакты специалистов без авторизации: так задумано, каталог
  публичный. Если потребуется закрыть их — снимите `OptionalJwtAuthGuard`
  с `SpecialistsController` и поставьте `JwtAuthGuard`.
