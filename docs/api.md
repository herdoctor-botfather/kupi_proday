# Справочник API

Базовый путь — `/api`. Формат обмена — JSON.

Ответы с ошибкой имеют единую форму:

```json
{ "statusCode": 404, "code": "SPECIALIST_NOT_FOUND", "message": "Специалист не найден" }
```

Поле `code` машиночитаемо — интерфейс решает по нему, что показать пользователю.

## Авторизация

Защищённые методы ожидают заголовок:

```
Authorization: Bearer <JWT>
```

### `POST /api/auth/telegram`

Единственный вход в приложение. Принимает сырую `window.Telegram.WebApp.initData`,
проверяет её HMAC-подпись на токене бота и возраст (не старше суток).

Из строки проверки исключается **только** поле `hash`. Поле `signature`
(подпись Ed25519 для сторонней проверки) в неё **входит**, хотя интуиция
подсказывает обратное. Если его отбросить, ни один вход из настоящего
клиента Telegram не пройдёт — а синтетические тесты при этом останутся
зелёными, если данные для них генерировать тем же ошибочным способом.

```json
{ "initData": "query_id=...&user=...&auth_date=...&hash=..." }
```

Ответ: `{ "token": "...", "user": { ... } }`

### `POST /api/auth/telegram-login`

Вход в веб-админку через Telegram Login Widget. Принимает payload виджета
целиком — все поля участвуют в проверке подписи, поэтому отбрасывать
неизвестные нельзя.

**Подпись здесь считается иначе, чем у Mini App**: секретный ключ — это
`SHA256(токен бота)`, а не `HMAC("WebAppData", токен)`. Подпись от Mini App
для этого маршрута недействительна, и наоборот.

Токен выдаётся только пользователям с ролью `ADMIN` или `MODERATOR`.
Остальные получают 401 с кодом `NOT_STAFF`. Максимальный возраст подписи — час.

### `POST /api/auth/dev`

Вход в админку без Telegram. Работает **только** при `NODE_ENV != production`
и заданном `ADMIN_DEV_TOKEN`. В продакшене метод всегда отвечает 401.

### `GET /api/auth/me` 🔒

Текущий пользователь.

## Каталог

### `GET /api/categories`

Активные категории со счётчиком опубликованных записей.

| Параметр | Тип | Описание |
| --- | --- | --- |
| `kind` | `SERVICE` \| `PRODUCT` | Набор категорий. По умолчанию `SERVICE` |

Наборы не пересекаются: `SERVICE` — категории специалистов, `PRODUCT` —
категории барахолки. Счётчик считает специалистов или объявления
соответственно.

### `GET /api/specialists`

Поиск и фильтрация. Все параметры необязательны.

| Параметр | Тип | Описание |
| --- | --- | --- |
| `q` | string | Поиск по имени, описанию, услугам и категориям |
| `categorySlug` | string | Фильтр по категории |
| `city` | string | Фильтр по городу |
| `minRating` | 1–5 | Минимальный рейтинг |
| `lat`, `lng` | number | Точка отсчёта; задаются только вместе |
| `radiusKm` | 0.5–200 | Радиус поиска, по умолчанию 10. Учитывается только с координатами |
| `sort` | `rating` \| `reviews` \| `distance` \| `new` | Сортировка. `distance` требует координат |
| `page`, `pageSize` | number | Постраничная выдача, `pageSize` до 50 |

Ответ — `Paginated<SpecialistListItem>`. При запросе с координатами каждая
карточка получает поле `distanceKm`.

### `GET /api/specialists/cities`

Города, в которых есть опубликованные карточки, со счётчиками. Принимает `q`
для поиска по подстроке. Используется подсказкой в форме анкеты и фильтром
в списке: свободный ввод города расслаивает каталог, а подсказка из
фактических значений сводит написания к одному без ручного справочника.

### `GET /api/specialists/map`

Маркеры для видимой области карты. Обязательны `north`, `south`, `east`, `west`;
дополнительно `categorySlug` и `limit` (до 500, по умолчанию 300).

Корректно обрабатывает область, пересекающую 180-й меридиан.

### `GET /api/specialists/:idOrSlug`

Полный профиль: контакты, услуги, галерея, разбивка оценок. Принимает и `id`, и `slug`.

Для авторизованного пользователя дополнительно возвращает его собственный
отзыв (`myReview`) и записывает просмотр в историю.

## Отзывы

### `GET /api/specialists/:id/reviews`

Опубликованные отзывы, новые сверху. Поддерживает `page` и `pageSize`.

### `POST /api/specialists/:id/reviews` 🔒

```json
{ "rating": 5, "text": "Всё отлично" }
```

Создаёт отзыв или заменяет собственный прежний. В обоих случаях отзыв
получает статус `PENDING` и не влияет на рейтинг до одобрения.

Ошибки: `SELF_REVIEW` — попытка оценить свою карточку.

### `DELETE /api/reviews/:id` 🔒

Удаление своего отзыва. Рейтинг пересчитывается.

### `PATCH /api/auth/onboarding` 🔒

Сохраняет выбор со стартового экрана: `{ "role": "CLIENT" | "SPECIALIST" }`.
На права не влияет — определяет только то, какой экран показать первым.

## Анкета специалиста 🔒

Специалист заводит и ведёт карточку сам. В отличие от админских методов здесь
недоступны статус, продвижение и `slug`: последний генерируется на сервере
транслитерацией имени, иначе можно было бы занять чужой адрес.

| Метод | Назначение |
| --- | --- |
| `GET /api/me/specialist` | Своя анкета или `null`, если не подавалась |
| `POST /api/me/specialist` | Подать анкету — создаётся со статусом `PENDING` |
| `PUT /api/me/specialist` | Изменить свою анкету |
| `POST /api/me/specialist/hide` | Убрать из каталога |
| `POST /api/me/specialist/publish` | Вернуть в каталог |

Тело запроса требует минимум: имя, город, хотя бы одну категорию и хотя бы один
способ связи. Координаты задаются только парой. Цены услуг передаются в рублях,
в базе хранятся в копейках.

Правила публикации:

- **новая анкета** не видна в каталоге до одобрения модератором;
- **правка опубликованной** карточки не снимает её с витрины, но выставляет
  `needsReview` — она попадёт в очередь повторной проверки. Убирать карточку
  из каталога из-за исправленной опечатки было бы слишком грубо;
- **правка отклонённой** анкеты снова отправляет её на проверку и сбрасывает
  причину отклонения;
- **скрытую** анкету, которая уже проходила модерацию, владелец возвращает
  без повторной проверки.

Ошибки: `PROFILE_EXISTS` — анкета уже есть (одна на пользователя),
`PROFILE_BLOCKED` — заблокирована администрацией.

## Переписка 🔒

Общение между заказчиком и специалистом идёт внутри приложения. Контакты
в публичной карточке не отдаются вовсе — поля `contacts` в ответе нет.

| Метод | Назначение |
| --- | --- |
| `POST /api/chat/conversations` | Открыть диалог: `{ specialistId }`. Повторный вызов возвращает существующий |
| `GET /api/chat/conversations` | Список диалогов, новые сверху |
| `GET /api/chat/unread` | Число непрочитанных для значка на вкладке |
| `GET /api/chat/conversations/:id` | Переписка. Открытие помечает входящие прочитанными |
| `POST /api/chat/conversations/:id/messages` | Отправить: `{ text }` |

Один диалог на пару «заказчик — специалист»: переписка должна быть сплошной,
а не рассыпаться на треды при каждом обращении.

**Контакты вычищаются на сервере** — и в сообщениях, и в анкете: описание,
заголовок и имя специалиста. Телефоны от семи цифр, `@username`, ссылки,
адреса почты и номера, продиктованные словами, заменяются на `[контакт скрыт]`.

Диктовка распознаётся по сумме цифр за числительными, а не по числу слов:
«сто» это три знака, «сорок» — два. Порог в семь цифр и минимум три
числительных подряд не даёт правилу срабатывать на «два кота и три собаки».

Исходный текст сохраняется в `originalText` — только для тех сообщений, где
было что скрывать, и только для разбора жалоб.

Каждая попытка увеличивает `contactAttempts` у пользователя. Первая приводит
к пояснительному сообщению от бота, третья — к уведомлению администраторов.

Сообщение, в котором после вычистки не остаётся ничего кроме меток,
отклоняется с кодом `EMPTY_MESSAGE`: иначе обмен контактами превратился бы
в обмен метками.

Посторонний получает `404`, а не `403`: по коду ответа не должно быть видно,
какие диалоги существуют.

Ошибки: `SELF_CHAT` — попытка написать себе, `SPECIALIST_UNREACHABLE` —
карточка заведена администратором и не привязана к аккаунту,
`CONVERSATION_BLOCKED` — переписка закрыта администрацией.

## Жалобы

### `POST /api/reports` 🔒

```json
{ "target": "SPECIALIST", "targetId": "...", "reason": "Мошенничество", "comment": "..." }
```

Причина выбирается из фиксированного списка (`REPORT_REASONS` в общем пакете),
для варианта «Другое» комментарий обязателен.

**Жалоба ничего не меняет автоматически.** Карточка остаётся в каталоге,
отзыв — на месте. Автоматическое скрытие по числу жалоб превратило бы их
в оружие: согласованными жалобами конкуренты снесли бы честную карточку.
Решение всегда принимает человек.

Один пользователь может пожаловаться на объект один раз — иначе очередь
модерации топится в повторах. На себя и на свой отзыв жаловаться нельзя.

Ошибки: `ALREADY_REPORTED`, `SELF_REPORT`, `TARGET_NOT_FOUND`.

| Метод | Назначение |
| --- | --- |
| `GET /api/admin/reports` | Очередь открытых жалоб с объектами, на которые пожаловались |
| `PATCH /api/admin/reports/:id` | `{ action: "resolve" \| "dismiss", note? }` |

### `POST /api/me/specialist/reviews/:id/reply` 🔒

Публичный ответ специалиста на отзыв о себе: `{ "text": "..." }`.
Пустая строка удаляет прежний ответ.

Модерацию ответ не проходит: он привязан к конкретному отзыву, виден рядом
с ним и подписан именем специалиста — злоупотребление бьёт по самому автору.
Отвечать можно только на опубликованные отзывы.

## Барахолка

Объявления о продаже вещей. Витрина открыта всем, размещение — по токену.

### `GET /api/listings`

Витрина. Видны только объявления со статусом `ACTIVE`, прошедшие модерацию.

| Параметр | Тип | Описание |
| --- | --- | --- |
| `q` | строка | Поиск по названию и описанию |
| `categorySlug` | строка | Категория из набора `PRODUCT` |
| `city` | строка | Город |
| `minPrice`, `maxPrice` | число | Границы цены в рублях |
| `condition` | `NEW` \| `USED_PERFECT` \| `USED` | Состояние товара |
| `sort` | `new` \| `cheap` \| `expensive` | По умолчанию `new` |
| `page`, `pageSize` | число | Постраничный вывод |

### `GET /api/listings/cities`

Города, в которых есть объявления, со счётчиком. Необязательный `q` — префикс.

### `GET /api/listings/:idOrSlug`

Карточка объявления: фотографии, категории, продавец. Контакты в названии и
описании заменены на `[контакт скрыт]` — переписка идёт только внутри бота.

### `GET /api/me/listings` 🔒

Свои объявления во всех статусах, включая ожидающие проверки и отклонённые.

### `POST /api/me/listings` 🔒

Разместить объявление. Тело:

| Поле | Тип | Ограничения |
| --- | --- | --- |
| `title` | строка | 3–120 символов |
| `description` | строка \| null | до 4000 символов |
| `price` | число | рубли, 0–1 000 000 000 |
| `isNegotiable` | boolean | торг уместен |
| `condition` | `NEW` \| `USED_PERFECT` \| `USED` | по умолчанию `USED` |
| `city` | строка | 2–100 символов |
| `categoryIds` | массив | 1–3 категории набора `PRODUCT` |

Цена приходит в рублях, хранится в копейках. Объявление создаётся со статусом
`PENDING` и на витрине не показывается, пока модератор его не одобрит.
Больше 20 активных объявлений на аккаунт завести нельзя.

### `PUT /api/me/listings/:id` 🔒

Правка. Опубликованное объявление с витрины не пропадает, но помечается
`needsReview` и попадает в очередь повторной проверки. Проданное не правится.

### `POST /api/me/listings/:id/sold` 🔒

Отметить проданным: объявление уходит с витрины, история переписок остаётся.

### `POST /api/me/listings/:id/hide` 🔒

Снять с витрины, не удаляя.

### `POST /api/me/listings/:id/publish` 🔒

Вернуть в продажу — в том числе проданное. Если объявление ранее прошло
модерацию, повторная проверка не нужна.

### `DELETE /api/me/listings/:id` 🔒

Удалить вместе с фотографиями, связями с категориями и переписками. `204`.

### `POST /api/me/listings/:id/photos` 🔒

`multipart/form-data`, поле `file`. До 10 фотографий; первая — обложка.
Возвращает объявление с обновлённым списком снимков.

### `DELETE /api/me/listings/photos/:photoId` 🔒

Удалить снимок вместе с файлом в хранилище. `204`.

## Изображения 🔒

Принимаются JPEG, PNG и WebP до 5 МБ. **Тип определяется по содержимому
файла, а не по заголовку `Content-Type`** — его присылает клиент, и подменив
заголовок, можно было бы загрузить что угодно под видом картинки.

Имя исходного файла не используется: в нём бывают недопустимые символы,
путь или чужое расширение. Ключ собирается как
`<назначение>/<id владельца>/<случайная строка>.<расширение>`.

| Метод | Назначение |
| --- | --- |
| `POST /api/uploads/image` | Загрузить изображение, вернёт `{ url, key }` |
| `POST /api/me/specialist/avatar` | Аватар анкеты; прежний файл удаляется |
| `POST /api/me/specialist/photos` | Снимок в галерею, до 12 штук |
| `DELETE /api/me/specialist/photos/:id` | Удалить снимок вместе с файлом |

Формат запроса — `multipart/form-data` с полем `file`. Заголовок `Content-Type`
задавать вручную не нужно: браузер добавит его вместе с `boundary`.

Mini App уменьшает снимок до отправки — фотография с телефона весит 5–10 МБ
при разрешении, которое каталогу не нужно.

Ошибки: `UNSUPPORTED_FILE` — не изображение, `FILE_TOO_LARGE` — больше 5 МБ,
`TOO_MANY_PHOTOS` — галерея заполнена.

## Админка 🔒

Требуется роль `ADMIN`; очередь модерации доступна и роли `MODERATOR`.

| Метод | Назначение |
| --- | --- |
| `GET /api/admin/stats` | Сводная статистика |
| `GET /api/admin/applications` | Очередь анкет: `pending` — новые, `changed` — правки опубликованных |
| `PATCH /api/admin/specialists/:id/moderate` | `{ action: "approve" \| "reject", reason? }` |
| `GET /api/admin/reviews/pending` | Очередь модерации отзывов, старые первыми |
| `PATCH /api/admin/reviews/:id` | `{ action: "approve" \| "reject", note? }` |
| `GET /api/admin/listings/pending` | Очередь объявлений: `pending` — новые, `changed` — правки опубликованных |
| `PATCH /api/admin/listings/:id/moderate` | `{ action: "approve" \| "reject", reason? }` |
| `GET /api/admin/specialists` | Список с фильтрами `q` и `status` |
| `POST /api/admin/specialists` | Создать карточку |
| `PUT /api/admin/specialists/:id` | Обновить карточку |
| `DELETE /api/admin/specialists/:id` | Удалить карточку |
| `GET/POST/PUT/DELETE /api/admin/categories` | Категории |
| `GET/POST /api/admin/specialists/:id/subscriptions` | Подписки специалиста |
| `POST /api/admin/subscriptions/expire` | Снять продвижение с истёкших подписок |

При отклонении отзыва поле `note` обязательно — причина показывается автору.

## Служебное

### `GET /api/health`

Проверка живости: выполняет запрос к БД и возвращает `{ "status": "ok", "uptimeSec": 1234 }`.
